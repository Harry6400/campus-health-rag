# 小组实际核验

这里不预填成员身份、结论或签名。AI生成的题目/评分只是初稿。

## 先检查什么
1. 打开本地 `review/private/questions-to-review.csv`。每题有问题、答案要点、真实原文依据与来源。
2. 核对“原文是否支持答案要点”“人群或条件是否遗漏”“无答案题是否真的缺依据”。不需要编写代码。
3. 有出入时填写评论，不要因为程序能读JSON就认定内容正确。
4. 当前120题中存在近似意图和范围需要复核；题目数量达到要求不等于数据质量通过。

## 正式运行前
`protocol.template.json` 只记录候选冻结值，当前状态仍为pending。24题结果复核样本已按题库文件顺序预选在 `formal-review-sample.json`：每个主题×题型取前2题，每主题1道直接题和1道无答案题双人复核；R1/R2是尚待映射的占位ID。样本共24题，两人各15题，不能把它写成已完成复核。

小组须实际核对语料来源与许可、题集采用方式、跨集概念关联披露、指标/评分口径、样本分配和正式配置。两名审核人各自确认同一范围后，才填写 `protocol.json`：记录R1/R2、真实审核日期和范围；姓名、原始确认文本及其对应关系保存在被 `.gitignore` 排除的 `review/private/formal-reviewer-identities.json`，协议只保存该文件的SHA-256。这样教师需要核对身份时仍可由小组单独出示私有记录，公开仓库不会默认暴露姓名或学号。不能让AI代签、推断队友意见或仅为绕过关卡填写approved。

正式守卫会比对题集、语料正文和清单、配置、DeepSeek官方供应商/地址/模型、回答与评分提示词、源代码/依赖锁、运行环境及复核样本指纹；并检查两名审核人身份记录哈希。API密钥只要求本地可用，绝不写入协议、运行指纹或公开日志。任一指纹变化都须重新审核。

不要求你们手动编辑JSON。实际检查后，可以在对话中说明核对了哪些内容、发现哪些问题，再由AI如实转录记录；没有做过的核对不能写完成。若资料或题集有修订，先处理修订，再重新核验并生成新指纹。

修改题集/配置、模型、提示词、代码、依赖或抽样都会改变冻结值，需要重新确认。审核记录包含的个人信息应留本地或在公开前适当去标识，不公开学号。

## 正式运行后
`campus-health export-review runs/<运行编号>` 导出真实输出待核验表。按方案实际复核24题的四种方法输出，其中6题两人重叠复核，记录分歧、理由与证据。AI可以先整理原文，不代替签名。
